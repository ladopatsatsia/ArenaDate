# ARENA — „დღეს მინდა…“

## გამოყენება

პრომტები მიეცი თანმიმდევრობით — თითოეულის დასრულებისა და შემოწმების შემდეგ გადადი შემდეგზე. პირველი პრომტი მხოლოდ პროექტის შესწავლასა და დაგეგმვას მოიცავს.

ყველა მომხმარებელი ხედავს თავისი გეგმის ყველა მსურველს ერთ სიაში. ორმხრივი მიღების შემდეგ გეგმის ჩატი უფასოა.

საწყისი ლიმიტები სამუშაო ვარიანტია და კონფიგურაციიდან უნდა იცვლებოდეს:

| შესაძლებლობა | უფასო | Premium |
| --- | --- | --- |
| ერთდროულად აქტიური გეგმები | 1 | 3 |
| სხვის გეგმებზე გამოხმაურება დღეში | 3 | 10 |
| ყველა მსურველის ნახვა | ყველას შეუძლია | ყველას შეუძლია |
| მიღების შემდეგ გეგმის ჩატი | უფასო | უფასო |

## პრომტი 1 — პროექტის შესწავლა და ფუნქციის დაგეგმვა

```text
ARENA-ში ვამატებთ ახალ განყოფილებას: „დღეს მინდა…“.

ჯერ წაიკითხე პროექტის ინსტრუქციები და შეისწავლე არსებული არქიტექტურა: backend, mobile frontend, ავტორიზაცია, პროფილები, Premium, ჩატი, შეტყობინებები, ბლოკირება, რეპორტები და ლოკალიზაცია.

ფუნქციის მიზანი:
მომხმარებელი აქვეყნებს კონკრეტულ გეგმას, მაგალითად „დღეს საღამოს ყავა ქუთაისში“. სხვები აგზავნიან „შემოგიერთდებოდი“ მოთხოვნას. ავტორი ხედავს ყველა მსურველს ერთ სიაში და ირჩევს ერთ ადამიანს. მიღების შემდეგ მათთვის უფასოდ იხსნება გეგმის ჩატი.

MVP:
- ერთი გეგმა ითვალისწინებს ერთ თანამგზავრს.
- გეგმები ჩანს ვერტიკალურ სიაში, დიდი ბარათებით.
- ფილტრები: ქალაქი, აქტივობა და დღე.
- აქტივობები: ყავა, სეირნობა, კინო, ჭამა, სხვა.
- მომხმარებელი უთითებს ქალაქს, სურვილისამებრ უბანს, სათაურს, მოკლე აღწერას, დაწყებისა და დასრულების დროს და სურვილისამებრ ბიუჯეტს GEL-ში.
- ზუსტი მისამართი და მომხმარებლის მიმდინარე მდებარეობა არ არის საჯარო.
- მოქმედებები: შექმნა, ნახვა, გამოხმაურება, მოთხოვნის უკან გამოთხოვა, მიღება/უარყოფა, გაუქმება.
- ვადის გასვლისას გეგმა ავტომატურად იწურება.

უფასო: 1 აქტიური გეგმა, 3 გამოხმაურება დღეში.
Premium: 3 აქტიური გეგმა, 10 გამოხმაურება დღეში.
ყველა მსურველის ერთ სიაში ნახვა ყველას შეუძლია.
მიღების შემდეგ გეგმის ჩატი უფასოა და კრისტალებს არ მოითხოვს.

გამოიყენე არსებული ტექნოლოგიები და კონვენციები. არ შექმნა პარალელური ავტორიზაციის, ჩატის ან Premium სისტემა.

ჯერ წარმოადგინე კონკრეტული განხორციელების გეგმა, საჭირო ცვლილებები და მნიშვნელოვანი გადაწყვეტილებები. ამ ეტაპზე კოდი არ შეცვალო.
```

## პრომტი 2 — მონაცემები და ბექენდი

```text
განახორციელე „დღეს მინდა…“ ფუნქციის მონაცემთა მოდელი, მიგრაციები და backend API წინა შეთანხმებული გეგმით.

გეგმის მდგომარეობები:
- Open: იღებს გამოხმაურებებს.
- Matched: ავტორმა მიიღო ერთი მსურველი.
- Cancelled: ავტორმა გააუქმა.
- Expired: დასრულების დრო გავიდა.

მოთხოვნის მდგომარეობები:
Pending, Accepted, Rejected, Withdrawn, Closed.
ერთი მსურველის მიღებისას დანარჩენი Pending მოთხოვნები გახდეს Closed.

დაამატე:
- გეგმების გვერდებად დაყოფილი საჯარო სია და დეტალები;
- ჩემი გეგმები და ჩემი გამოხმაურებები;
- შექმნა და გაუქმება;
- „შემოგიერთდებოდი“ სურვილისამებრ მოკლე მესიჯით;
- მოთხოვნის გამოთხოვა;
- ავტორისთვის ყველა მსურველის გვერდებად დაყოფილი სია;
- მიღება და უარყოფა.

აუცილებელი წესები:
- ავტორი საკუთარ გეგმაზე ვერ გამოეხმაურება.
- ერთ მომხმარებელს ერთ გეგმაზე მაქსიმუმ ერთი მოთხოვნა ჰქონდეს; Withdrawn-ის შემდეგ MVP-ში ხელახლა გაგზავნა არ დაუშვა.
- დახურულ ან ვადაგასულ გეგმაზე მოთხოვნა ვერ გაიგზავნება.
- მოთხოვნებს მხოლოდ ავტორი და შესაბამისი განმცხადებელი ხედავენ.
- დაბლოკილი მომხმარებლები ერთმანეთის გეგმებსა და მოთხოვნებზე წვდომას ვერ იღებენ.
- დრო შეინახე UTC-ში; მომხმარებლისთვის წარმოადგინე ადგილობრივი დროით.
- მაქსიმალური დაგეგმვის ჰორიზონტი იყოს კონფიგურირებადი, საწყისად 48 საათი.
- ბიუჯეტი იყოს სურვილისამებრ; მინიმუმი/მაქსიმუმი სწორად მოწმდებოდეს.
- ერთ გეგმაზე ორი მოთხოვნის ერთდროული მიღება ატომურად გამოირიცხოს.
- გამოიყენე არსებული validation, error response და authorization ფორმატი.

დაამატე საჭირო ინდექსები და მნიშვნელოვანი ბიზნესწესების ტესტები.
```

## პრომტი 3 — ლიმიტები და Premium

```text
დაამატე „დღეს მინდა…“ ფუნქციის backend-ზე აღსრულებადი ლიმიტები არსებული Premium სისტემის გამოყენებით.

კონფიგურირებადი საწყისი მნიშვნელობები:
Free: 1 აქტიური გეგმა, 3 გამოხმაურება დღეში.
Premium: 3 აქტიური გეგმა, 10 გამოხმაურება დღეში.

აქტიური გეგმა არის Open ან Matched მდგომარეობაში არსებული გეგმა, რომლის დასრულების დროც ჯერ არ გასულა.

დღიური ლიმიტი ეხება მხოლოდ სხვის გეგმებზე გაგზავნილ ახალ მოთხოვნებს.
გეგმის მიღება, უარყოფა, ნახვა და მიღებული მოთხოვნები ამ ლიმიტში არ ითვლება.
მოთხოვნის გამოთხოვა დახარჯულ გამოხმაურებას არ აბრუნებს.
წარუმატებელი მოთხოვნა ლიმიტს არ ხარჯავს.

გამოიყენე ანგარიშის დროის სარტყელი, თუ პროექტში არსებობს; წინააღმდეგ შემთხვევაში საწყისი იყოს Asia/Tbilisi. იგივე წესი გამოიყენე backend-სა და UI-ში.

დააბრუნე მიმდინარე გამოყენება, ლიმიტი და განახლების დრო.
ერთდროულმა მოთხოვნებმა ლიმიტს ვერ გადააჭარბოს.

Premium-ის გაუქმებისას არსებული გეგმები არ წაშალო; ახალი გეგმის შექმნა შეიზღუდოს, სანამ გამოყენება დაშვებულ ზღვარზე არ ჩამოვა.

ყველა მსურველის სია და მიღების შემდეგ ჩატი უფასოა.
ტესტებით გადაამოწმე ზღვარი, დღის ცვლილება და ერთდროული მოთხოვნები.
```

## პრომტი 4 — უფასო ჩატი და შეტყობინებები

```text
დაუკავშირე გეგმის მოთხოვნის მიღება არსებულ ჩატსა და შეტყობინებებს.

მოთხოვნის მიღებისას:
- გეგმა გახდეს Matched.
- შეინახოს არჩეული თანამგზავრი.
- ორივეს მიეცეს უფასო წვდომა გეგმის კონტექსტის მქონე ჩატზე.
- კრისტალები არ ჩამოიჭრას და გადახდის ფანჯარა არ გამოჩნდეს.
- განმეორებით მოთხოვნას დუბლირებული ჩატი ან შეტყობინება არ მოჰყვეს.

თუ ორ მომხმარებელს უკვე აქვთ პირადი ჩატი, გაითვალისწინე არსებული არქიტექტურა:
არ გახსნა სხვა კონტექსტში ფასიანი შესაძლებლობები შემთხვევით; უფასო წვდომა მკაფიოდ დაუკავშირე ამ გეგმის მიღებას.

გაგზავნე შეტყობინებები:
- ავტორს ახალი გამოხმაურების შესახებ;
- მსურველს მიღების შესახებ;
- არჩეულ თანამგზავრს გეგმის გაუქმების შესახებ.

გეგმის გაუქმება ან ვადის გასვლა არ შლის მიმოწერის ისტორიას.
ბლოკირება და რეპორტი მუშაობდეს არსებული წესებით.
შეტყობინებიდან გაიხსნას შესაბამისი გეგმა, მსურველების სია ან ჩატი.

უზრუნველყავი მიღების პროცესის თანმიმდევრულობა, მათ შორის შეტყობინების გაგზავნის ჩავარდნისას.
```

## პრომტი 5 — აპლიკაციის ინტერფეისი

```text
შექმენი „დღეს მინდა…“ განყოფილების სრული mobile UI არსებული დიზაინსისტემის გამოყენებით.

- ვერტიკალური სია დიდი ბარათებით;

- გეგმის შექმნის ღილაკი;
- „ყველა გეგმა“, „ჩემი გეგმები“, „ჩემი გამოხმაურებები“.

ბარათზე:
ფოტო, სახელი, ასაკი, აქტივობა, სათაური, ქალაქი/უბანი, დრო, სურვილისამებრ ბიუჯეტი და „შემოგიერთდებოდი“.

დაამატე:
- გეგმის შექმნის მარტივი ფორმა;
- დეტალები და მოკლე მესიჯით გამოხმაურება;
- ავტორისთვის ყველა მსურველის ერთ სიაში ნახვა, პროფილის გახსნა, მიღება/უარყოფა;
- მიღების შემდეგ ჩატში გადასვლა;
- გაუქმება დადასტურებით;
- გამოხმაურების უკან გამოთხოვა;
- მიმდინარე ლიმიტების ჩვენება და Premium შეთავაზება მხოლოდ შესაბამისი ლიმიტის ამოწურვისას.

ყველას შეუძლია მსურველების სრული სიის ნახვა საკუთარ გეგმაზე.

გაითვალისწინე loading, empty, error, retry, pagination და ორმაგი დაჭერისგან დაცვა.
სერვერის მდგომარეობა იყოს საბოლოო ჭეშმარიტება.
```

## პრომტი 6 — ვადები და საბოლოო შემოწმება

```text
დაასრულე „დღეს მინდა…“ ფუნქციის lifecycle და შეამოწმე სრული ინტეგრაცია.

არ გამოაცხადო დასრულებულად ფუნქცია, თუ UI ჯერ mock მონაცემებზე მუშაობს.
```
